# Skeleton — Repository Projection Pipeline

```
map.py          scans for real markers, emits a CITED pack + derived blast radius
drift.py        compares the pack against the repository as it is now
fixture-repo/   three components with declared dependencies
pack.json       GENERATED by map.py — not committed, since it
                carries a timestamp and would dirty the tree on every run
```

## Try it

```bash
python3 map.py                              # generate the pack
python3 drift.py                            # exits 0 — no drift yet

mkdir -p fixture-repo/scheduler && printf 'name: scheduler\ndependencies:\n  - name: api\n' > fixture-repo/scheduler/Chart.yaml
python3 drift.py                            # exits 1 — the pack is now stale

rm -rf fixture-repo/scheduler && python3 drift.py   # clean again
```

Two things to notice.

**Every claim cites a file.** That is what makes the pack checkable. `drift.py`
does not read the pack for plausibility — it resolves the citations. A document
that cannot be re-tested can only be trusted.

**Blast radius is derived, not asserted.** `map.py` computes dependent counts
from the declared dependencies and assigns tiers from them. A hand-maintained
matrix like the one in [card 17](../17-blast-radius-gating/) goes stale with
every architectural change; this one regenerates with the pack.

## What is deliberately missing

**The generate stage.** `map.py` produces the pack; nothing turns it into the
documents a reader or an agent consumes. That middle stage is where the
residual questions — intent, ownership, rationale — get asked, and their
answers are the one part a regeneration destroys.

**A trigger.** `drift.py` runs when you run it. In the source system the
detector existed, was never triggered, and the most carefully evidenced artifact
in the kit quietly became the thing
[card 05](../../cards/05-instruction-provenance-and-drift.md) warns about.
